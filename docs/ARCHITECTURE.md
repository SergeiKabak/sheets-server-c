# Архитектура

Сервер — Telegram-бот с webhook и Mini App (график смен). Код разбит по слоям
так, чтобы зависимости шли только сверху вниз, а побочные эффекты (сеть, файлы,
часы) были отделены от чистой логики.

```
src/
  core/     чистые функции: нет I/O, нет глобального состояния
  domain/   модель предметной области и чистые преобразования над ней
  infra/    адаптеры внешнего мира: HTTP, Google, Supabase, Telegram, ФС, часы
  app/      сценарии использования (то, что делает сервер)
  web/      HTTP-обработчики: превращают результаты сценариев в ответы
  server/   приём соединений и маршрутизация
  vendor/   сторонние библиотеки (cJSON, мини-шим curl)
  main.c    composition root: собирает зависимости и запускает сервер
```

Правило: `core` и `domain` не знают про сеть; `infra` не знает про сценарии;
`app` не знает про HTTP-детали сокета. Слой `web` только пишет байты в сокет.

## Слои

### core — чистое ядро

| Модуль | Что делает |
|---------|------------|
| `core/json_text` | экранирование строк для JSON, чтение полей JSON-документа |
| `core/strbuf` | наращиваемый буфер строки (вместо ручной арифметики offset) |
| `core/url_codec` | кодирование/декодирование URL, разбор query-строки |
| `core/date_time` | даты, время, названия месяцев (без «сейчас») |
| `core/shift` | разбор и сравнение смен «7:30-14:40» |
| `core/num` | разбор и форматирование чисел |

Единственное экранирование JSON на весь проект — здесь. Раньше оно было
продублировано в трёх модулях с разным поведением.

### domain — модель

| Модуль | Что делает |
|---------|------------|
| `domain/timesheet` | лист учёта времени: строки по 6 ячеек, поиск блоков, сортировка дат, сборка `values.update` |
| `domain/schedule` | график смен: месяц-лист, строки месяца из БД, список коллег |
| `domain/reminder` | планы напоминаний: разово на завтра и по графику (начало/конец смены) |
| `domain/time_entry` | отметки времени: JSON дней, расчёт часов и суммы |

### infra — внешний мир

| Модуль | Что делает |
|---------|------------|
| `infra/http_client` | единственный модуль, знающий про curl |
| `infra/google_auth` | OAuth2 Service Account -> access_token (кэш в памяти и в файле) |
| `infra/google_sheets` | Google Sheets API: чтение, запись, создание вкладок |
| `infra/supabase` | PostgREST: буфер графика и `time_entries` |
| `infra/telegram_api` | отправка сообщений и ответы на callback-запросы |
| `infra/file_store` | атомарная запись файлов кэша (tmp + rename) |
| `infra/clock` | «сейчас» — единственный источник текущего времени |

### app — сценарии

| Модуль | Что делает |
|---------|------------|
| `app/config` | конфигурация из переменных окружения (читается один раз) |
| `app/context` | объект, связывающий конфигурацию, сервис учёта и бота |
| `app/tracking_service` | учёт времени: приход/уход, заполнение дня, правка, удаление, выгрузка |
| `app/tracking_cache` | кэш отметок по месяцам и флаги «выгрузить в Google» |
| `app/schedule_service` | сбор месяцев из Google Sheets, коллеги по кабинету |
| `app/month_cache` | файловые кэши графика (месяцы, индекс кабинетов, mresp, mcol) |
| `app/month_api` | сценарии Mini App: список месяцев, график месяца, коллеги |
| `app/bot_service` | разбор Telegram-update и ответы в чат |
| `app/reminder_service` | напоминания: сохранение, режим «по графику», отправка |
| `app/background` | фоновый цикл: обновление кэшей, синхронизация с БД, напоминания |

### web и server

| Модуль | Что делает |
|---------|------------|
| `web/http_reply` | формирование HTTP-ответов |
| `web/static_files` | раздача `web/` с ETag и Cache-Control |
| `web/api_schedule` | `/api/months`, `/api/month`, `/api/cabinet` |
| `web/api_tracking` | `/api/tracking/*`, `/diag/tracking*` |
| `web/diag` | `/diag`, `/diag/cabinet`, `/diag/supabase` |
| `server/http_server` | сокет, приём запроса, fork на соединение |
| `server/router` | таблица маршрутов |

## Принципы

**Чистое ядро.** Вся логика, которую можно проверить без сети, вынесена в
`core` и `domain`. Она принимает данные и возвращает данные; побочных
эффектов в ней нет вообще. Это проверяется тестом `make test-core` — он
работает мгновенно и не требует ни сети, ни файлов.

**Явные зависимости.** Раньше модули тянули глобальные переменные (`SEARCH_NAME`,
`BOT_TOKEN`, id таблицы, access_token). Теперь всё передаётся аргументами:
`AppConfig` — конфигурация, `TrackingService` — состояние сервиса учёта,
`AppContext` — то, что нужно приложению целиком. Создаёт их один модуль —
`main.c` (composition root), и сразу видно, что за чем запускается.

**Нет скрытых состояний.** Кэши и буферы — отдельные модули с явным API
(`trk_cache_read` / `trk_cache_write`, `sb_row` / `sb_flush`). Модуль не
знает, кто его вызывает.

**Функции высшего порядка.** Предикаты передаются указателями: например,
`ShiftFilter` — «пересекаются ли смены», а `colleagues_from_rows_json` принимает
любой предикат. Один и тот же код сборки коллег работает и для строк из БД,
и для строк из файлового индекса.

**Ошибки — значения, а не исключения.** Функции возвращают код (`0 — успех`,
`-1 — нет данных`), а не меняют глобальные флаги. Наружу отдаётся конкретный
HTTP-код и JSON с текстом ошибки.

## Тесты

| Команда | Что проверяет |
|---------|---------------|
| `make test-core` | чистое ядро: даты, смены, JSON, URL, лист, отметки (без сети) |
| `make test-supabase` | буфер Supabase и разборы из слоя domain |
| `make test` | сценарии учёта времени с подменённым HTTP-слоем |
| `make test-js` | логика Mini App (jsdom) |
