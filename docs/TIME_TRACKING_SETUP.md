# Настройка учёта рабочего времени (Time tracking)

Кнопки «Пришла» / «Ушла» в Telegram Web App пишут записи в таблицу
**Time tracking** (`1zhWZRFI6GYYnh6PNQn37KiSyPLvjkSwJz-CKwF0xEnw`).

## Структура листа

Вкладка создаётся автоматически и называется по текущему месяцу и году
(например, `Октябрь 2026`). Колонки:

| A | B | C | D | E | F |
|---|---|---|---|---|---|
| Дата | Время прихода | Время ухода | Время в часах | Ставка в час | Сумма за день |

Блоки разных сотрудников разделены пустой строкой. Перед блоком стоит строка
с ФИО сотрудника.

## Почему нужен Service Account

Google Sheets API **запрещает запись по API key** (`401: API keys are not
supported by this API`). Поэтому для записи используется OAuth2 — JWT (RS256),
подписанный приватным ключом Service Account.

## Настройка (один раз)

### 1. Создать Service Account

1. Откройте https://console.cloud.google.com/
2. Создайте проект (или выберите существующий).
3. **IAM & Admin → Service Accounts → Create service account**
4. Имя, например `sheets-tracker`. Нажмите **Create and continue**.
5. Роль (**Grant this service account access to the project**) — **не нужна**,
   снимите галочку или оставьте пустым, нажмите **Continue**.
6. На экране ключей: **Create new key → JSON**. Скачается файл
   вида `sheets-tracker-xxxxx.json`.

### 2. Выбрать один из двух вариантов

#### Вариант А (проще) — сервер создаст таблицу сам

Сервер умеет **сам создать таблицу** `Time tracking` через Service Account
и выдать вам права. Тогда шаг с ручным созданием таблицы не нужен.

В Render задайте:

| Переменная | Значение |
|------------|----------|
| `TRACKING_SHEET_ID` | оставьте пустым / удалите |
| `TRACKING_SHARE_EMAIL` | ваш email (например `ivanov@gmail.com`) |
| `TRACKING_SHEET_TITLE` | `Time tracking` (необязательно) |

При первом нажатии «Пришла» сервер:
1. создаст таблицу с именем `Time tracking` (владелец — Service Account);
2. выдаст вам права **Редактор**;
3. сохранит ID таблицы в `/tmp/tracking_sheet_id`.

> Нужно включить **Drive API** в проекте Service Account:
> https://console.developers.google.com/apis/api/drive.googleapis.com/overview?project=ВАШ_ПРОЕКТ
> (иначе авто-выдача прав не сработает — таблица создастся, но вы её не увидите).

Ссылку на созданную таблицу сервер выведет в лог Render:
```
[track] created spreadsheet 'Time tracking' id=1a2b... url=https://docs.google.com/spreadsheets/d/1a2b...
```

#### Вариант Б — использовать уже созданную таблицу

1. Откройте таблицу Time tracking:
   https://docs.google.com/spreadsheets/d/1zhWZRFI6GYYnh6PNQn37KiSyPLvjkSwJz-CKwF0xEnw/edit
2. Кнопка **Поделиться** (Share) → **Добавить пользователей и группы**.
3. В поле вставьте email сервисного аккаунта:
   `sheets-tracker@ВАШ_ПРОЕКТ.iam.gserviceaccount.com`
4. Роль: **Редактор** (Editor).
5. Нажмите **Отправить** / **Готово**.

В Render: `TRACKING_SHEET_ID=1zhWZRFI6GYYnh6PNQn37KiSyPLvjkSwJz-CKwF0xEnw`

> Важно: если таблица закрыта («Ограниченный доступ»), пригласите и себя.

### 3. Задать переменные окружения в Render

В панели Render: **ваш сервис → Environment → Add Environment Variable**

| Переменная | Значение |
|------------|----------|
| `TRACKING_SHEET_ID` | `1zhWZRFI6GYYnh6PNQn37KiSyPLvjkSwJz-CKwF0xEnw` — либо пусто, если сервер создаёт таблицу сам |
| `TRACKING_SHARE_EMAIL` | ваш email — чтобы получить права на созданную сервером таблицу |
| `TRACKING_SHEET_TITLE` | `Time tracking` (необязательно) |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | **Весь содержимое скачанного JSON-файла** (одной строкой) |
| `HOURLY_RATE` | `500` (ставка по умолчанию) |
| `TZ_OFFSET_SECONDS` | `10800` (Москва = UTC+3). По умолчанию 10800 |
| `SUPABASE_URL` + `SUPABASE_SECRET_KEY` | БД — первоисточник учёта времени (см. `SUPABASE_PLAN.md`) |

> Сотрудник и его ФИО берутся из переменной `SEARCH_NAME` (та же, что для
> графика смен). Переменные `EMPLOYEE_MAP` / `EMPLOYEE_RATES` больше не
> используются — остались только в истории.

Содержимое JSON-файла сервисного аккаунта — **одна длинная строка**. Пример:

```
{"type":"service_account","project_id":"my-project","private_key_id":"abc...","private_key":"-----BEGIN PRIVATE KEY-----\nMIIEvQ...\n-----END PRIVATE KEY-----\n","client_email":"sheets-tracker@my-project.iam.gserviceaccount.com","client_id":"123","token_uri":"https://oauth2.googleapis.com/token"}
```

Переносы строк внутри JSON уже экранированы как `\n` — вставляйте как есть.

### 4. Как узнать chat_id сотрудника

chat_id — это числовой ID пользователя в Telegram. Проще всего:
1. Создайте бота через [@BotFather](https://t.me/BotFather) (или используйте
   существующего), отправьте ему `/start`.
2. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — в ответе будет
   `"chat":{"id":123456789,...}`.

### 5. Деплой

После добавления переменных Render пересоберёт сервис. Затем проверьте:

```bash
# сервис жив
curl "https://sheets-server-c.onrender.com/health"     # -> OK

# диагностика учёта времени: наличие Service Account, токен, вкладки,
# чтение текущего месяца (read_ok:true — всё настроено)
curl "https://sheets-server-c.onrender.com/diag/tracking"
```

## Как это работает

**БД — первоисточник, Google — архив.** Запись идёт сразу в Supabase
(`time_entries`), а Google-лист обновляется фоновым процессом (в течение
минуты, либо раз в сутки для правок дашборда). Если БД недоступна — запись
идёт в Google напрямую (фоллбэк), а при восстановлении БД фон догонит
разницу. Подробности — в `SUPABASE_PLAN.md`.

1. Запрос приходит от бота (кнопки «Пришла»/«Ушла») или из Mini App
   (кнопка «+» по дню / правка / удаление).
2. Сервер определяет сотрудника по `SEARCH_NAME`, ставку — из `month_rates`
   для месяца записи; если для месяца ставка не задана — из `HOURLY_RATE`.
3. Для вкладки текущего месяца (`MM.YYYY`, например `10.2026`) находится
   строка сотрудника и его строка за сегодня:
   - **«Пришла»** — записывает время прихода (повтор — ошибка 409).
   - **«Ушла»** — записывает время ухода, считает часы и сумму
     (повтор — ошибка 409).
4. Часы = (уход − приход) в часах, Сумма = часы × ставка месяца.

Проверка подписи `initData` (HMAC-SHA256 от токена бота) в коде реализована,
но **пока отключена**: сервер обслуживает одного сотрудника, заданного в
`SEARCH_NAME`.

## Кто владелец таблицы

- **Вариант А** — владелец таблицы это Service Account
  (`sheets-tracker@проект.iam.gserviceaccount.com`). Вы получаете права
  Редактора через `TRACKING_SHARE_EMAIL`.
- **Вариант Б** — владелец остаётся ваш Google-аккаунт, Service Account
  добавляется как Редактор.

Сам я (AI-ассистент) не могу быть владельцем таблицы Google: для этого нужен
вход в ваш Google-аккаунт (логин, 2FA, подтверждение), а такие действия
нельзя автоматизировать. Но через Service Account это делает сам сервер —
и вы остаётесь полноправным редактором.

## Заполнение отработанного времени из графика

В Mini App под таблицей графика есть блок «Учёт рабочего времени».
В ячейках графика, где указан кабинет, но время за этот день ещё не внесено
в таблицу Time tracking, показывается зелёная кнопка **«+»**:

1. откройте нужный месяц (в том числе прошлый — он берётся из расписания);
2. нажмите **«+»** в ячейке нужного дня;
3. проверьте время прихода и ухода — оно подставляется из смены графика
   (например, `7:30-14:40`), при необходимости измените;
4. нажмите **«Сохранить»**.

Сервер сам создаст вкладку месяца, если её ещё нет, добавит строку
сотрудника и посчитает часы и сумму. Имя новой вкладки — цифрами:
`10.2026` для октября 2026 года. После сохранения «+» заменяется на
зелёную галочку, а в таблице появляется запись.

Если в таблице уже стоит приход, но нет ухода, «+» остаётся — при нажатии
поле прихода будет заполнено из таблицы, нужно указать только уход.

### Правка и удаление дней

Тап по **уже отмеченному** дню открывает тот же диалог с предзаполненными
значениями и подсказкой «Сейчас отмечено: …»:

- **Сохранить** — правка: день в БД перезаписывается (это не конфликт).
- **Удалить время** — день удаляется из БД; фоновый процесс вычищает
  соответствующую строку и в Google-листе (дата и ставка в листе
  сохраняются).

### Ставка за час на месяц

В блоке «Учёт рабочего времени» под кнопкой **«Деньги»** есть поле
**«Ставка за час, ₽»** и кнопка **«Сохранить»**. Ставка относится к месяцу,
который сейчас открыт в календаре:

- сохраняется в таблице `month_rates` (ключ — `10.2026`);
- если для месяца ставки нет, показывается и применяется `HOURLY_RATE`
  из окружения (по умолчанию 500) — старые месяцы ничего не теряют;
- при изменении ставки сервер **пересчитывает суммы всех уже отмеченных
  дней этого месяца** и сбрасывает кэш, поэтому новые суммы видны сразу;
- колонка E в Google-листе обновляется фоновой выгрузкой: явная ставка
  месяца записывается во все строки-дни этого месяца, суммы в F берутся
  из БД.

Перед первым использованием нужно один раз создать таблицу:
`docs/sql/month_rates.sql` → выполнить в Supabase SQL Editor. Без неё
кнопка вернёт ошибку, а чтение ставки будет отдавать `HOURLY_RATE`.

### Кэш и скорость

Чтобы не ждать ни БД, ни Google при каждом переключении месяца, список
отмеченных дней кешируется в `/tmp/trk_days_<MM.YYYY>.json`. Фоновый процесс,
который и так обновляет расписание раз в 60 секунд, в том же цикле обновляет
и этот кэш **из БД** (первоисточник; Google — только фоллбэк). `GET /api/month`
сразу возвращает поле `trk` из кэша, поэтому «+» и галочки появляются вместе
с таблицей графика без второго запроса.

- если кэша нет или он старше 90 секунд — данные читаются из БД,
  а при её недоступности — из Google;
- после «Пришла», «Ушла», заполнения дня или удаления кэш месяца сбрасывается,
  чтобы следующее открытие показало актуальное состояние;
- для месяцев, которых ещё нет в Time tracking, в кэш пишется пустой
  список дней — все кабинеты сразу получают «+».

### API

| Метод | Путь | Назначение |
|-------|------|------------|
| GET | `/api/tracking/days?month=Октябрь%202026` | дни месяца, которые уже отмечены |
| POST | `/api/tracking/fill?month=Октябрь%202026&day=7&in=07:30&out=14:40` | записать/изменить отработанное время за день |
| POST | `/api/tracking/erase?month=Октябрь%202026&day=7` | удалить отметку дня |
| GET | `/api/tracking/rate?month=Октябрь%202026` | ставка за час месяца (`source`: `month` или `default`) |
| POST | `/api/tracking/rate?month=Октябрь%202026&rate=600` | сохранить ставку месяца и пересчитать суммы всех дней |
| GET | `/api/tracking/clock?action=in\|out` | отметка прихода/ухода (из бота или Mini App) |
| GET | `/api/tracking/summary?month=...&name=...` | сводка по сотруднику |
| GET | `/api/tracking/months` | список месяцев с заработком |
| GET | `/diag/tracking` | диагностика: Service Account, токен, вкладки, чтение |
| GET | `/diag/tracking/ensure?month=...` | создать вкладку месяца (диагностика) |

`month` принимает и название (`Октябрь 2026`), и номер вкладки (`10.2026`).
Будущие даты не принимаются — учитывается только уже отработанное время.

## Ограничения

- Одна запись на сотрудника в день: повторное «Пришла» или повторное «Ушла»
  вернёт ошибку 409. Повторное заполнение дня (`fill`) — это правка, а не
  ошибка.
- Чтение мгновенное (из БД или кэша); выгрузка в Google — в течение минуты
  фоновым процессом, а правки дашборда Supabase — раз в сутки.
- access_token кэшируется в памяти процесса и в файле `/tmp/trk_sa_token`,
  обновляется за пару минут до истечения.
